# آزمایشگاه طراحی رسیدیم

نشانی پس از استقرار: `/test/`. تست‌ها: `/test/1/` تا `/test/n/`.

- فهرست HTML واقعی است؛ بدون JavaScript هم لینک‌ها کار می‌کنند.
- دقیقاً سه ستون در همه عرض‌ها: هر دکمه یک‌سوم فضای موجود، با کسر فاصله ستون‌ها.
- تست تازه در بالای فهرست قرار می‌گیرد؛ شماره‌ها از ۱ افزایشی‌اند.
- نسخه‌های قدیمی و `assets/v1` ثابت‌اند؛ برای تغییر، تست جدید یا assets/v2 بسازید.
- انتخاب پسندیده و ظاهر روی همین دستگاه ذخیره می‌شود؛ به سرور ارسال نمی‌شود.
- تست ۲ از DaisyUI واقعی CDN استفاده می‌کند؛ fallback محلی وجود دارد. تست ۳ الهام از Material است، نه اجرای کتابخانه رسمی آن.
- PWA این آزمایشگاه فقط scope مسیر `/test/` دارد؛ از اپ اصلی مستقل است. نصب به HTTPS و پشتیبانی مرورگر وابسته است. فایل‌های خارجی CDN آفلاین تضمین نمی‌شوند؛ ظاهر محلی و عملکرد پایه کار می‌کنند.

## اضافه‌کردن تست

اول صفحه کامل و دارایی‌های محلی آن را در پوشه‌ای بیرون از `test/` بسازید. فایل index.html ضروری است. مسیرهای assets را نسبت به مقصد نهایی تنظیم کنید. پوشه منبع را داخل خودش یا داخل پوشه مقصد قرار ندهید.

```sh
python3 scripts/design_lab.py --source /absolute/path/completed-design --title 'عنوان طرح' --direction 'جهت هنری'
python3 scripts/design_lab.py --check
```

اسکریپت فولدر بعدی را می‌سازد، registry را اضافه می‌کند و index را تازه‌ترین‌اول می‌نویسد. برای بازسازی فهرست بدون افزودن تست: `python3 scripts/design_lab.py`.

تست‌های تازه بعد از بازدید آنلاین آفلاین می‌شوند؛ سه تست اول از ابتدا پیش‌ذخیره می‌شوند. آفلاین امکان ثبت واقعی سفر، حساب یا ورود ندارد.

## بازخورد

پسند دقیق را در `docs/design/FEEDBACK.md` ثبت کنید: شماره، چیز موردعلاقه، چیز نامطلوب و تغییر مطلوب. انتخاب مرورگر به‌تنهایی این فایل را به‌روز نمی‌کند.
